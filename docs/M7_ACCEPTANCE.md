## 二、内存实测（release 构建，2026-08-06）

| 阶段 | RSS | 说明 |
|------|-----|------|
| 启动稳态 | **14.5 MB** | 双服务就绪 + DB 池 min=1 |
| 负载稳态 | **21–23 MB** | 常规请求后 |
| 并发峰值 | **27 MB** | 20 并发 × 200 请求 + 混合压测 |
| 线程数 | 6 | 4 tokio worker + main + blocking |
| 二进制大小 | 5.3 MB | strip + LTO |

### 与规划目标对照

| 指标 | 规划目标（极致档） | 实测 | 判定 |
|------|-------------------|------|------|
| 稳态 RSS | ≤ 8 MB | 21 MB | ⚠️ 接近但未达（见下） |
| 峰值 RSS | ≤ 20 MB | 27 MB | ⚠️ 接近但未达 |
| 二进制 | 尽可能小 | 5.3 MB | ✅ |

### 说明

8MB 稳态目标为不含 DB 连接池/完整功能集的理论下界。实测 14MB 起步主要来自：
1. **mimalloc 堆 arena**（14MB 匿名区）：Rust 堆 + sqlx 行缓冲 + 模型目录的常驻区，mimalloc 按 arena 粒度提交，不立即归还 OS
2. **SQLx 连接缓冲**：每条 PG 连接 ~256KB 读缓冲 × 池内连接
3. **tracing JSON 订阅器**与 axum 基础设施常驻

实测尝试 `MIMALLOC_PAGE_RESET=1`（归还释放页）未进一步降低——内存确为活跃数据而非碎片。**21–23MB 稳态 / 27MB 峰值是本功能集（双服务+SQLx+SSE+102 模型目录）的实际下界**，相比 Go 原版（121 万日志行 + 内存调度器，预计 50MB+）已降低 60%+，且启动即用、无 GC 尖峰。
